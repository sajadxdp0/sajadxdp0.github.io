# Portfolio Site

> Maintainer doc. Static site, hosted by GitHub Pages at sajadxdp0.github.io.
> Codebase: `~/github-migration/site` | Stack: vanilla HTML + CSS + JS, no build.

## 1. What this product is

Personal portfolio for Sajad. The landing is the About page
(Sajad.); Projects (Lexora, HookFlow, EsenceLab, neuDB) and
Contact are the other two pages. Goal: bring visitors to GitHub /
LinkedIn / email contact. No blog, no feed, no archive, no subpages.

## 2. How it works

- Three pages: `index.html` (the About page), `projects.html`,
  `contact.html`. No 404 page, no project subdirectories. Every
  project title links its GitHub repo directly.
- `style.css` (edition 12, black and white only: ground `#0a0a0a`,
  paper `#f5f5f5`, greys `#bcbcbc`/`#8a8a8a`, hairlines `#2a2a2a`/`#1f1f1f`;
  62rem document column, 42rem read column, numbered flat title rows,
  mono meta text, no looping motion)
- `assets/clouds.png` — ordered-dither cloud band, used only behind the
  landing copy and faded out at both edges with mask gradients
- `script.js` (footer year, active-nav marking, mailto copy button)
- Discovery: `sitemap.xml` (3 urls), `robots.txt`, OG meta/`og.png`, `favicon.svg`
- No templating: header/nav/footer duplicated per file (drift risk, see roadmap)

## 3. User guide

### Serve locally
```bash
python3 -m http.server -d ~/github-migration/site 8000
```

### Edit content
- Hero is the name `Sajad` over the dithered cloud band (the landing,
  which is the About page). The cloud art is generated by a script kept
  outside the repo; edit `assets/clouds.png` only with a new dither pass.
- Project blurbs: `projects.html` only (keep in sync with the
  GitHub profile README)
- Styles/nav: `style.css`, each page's `<nav>`

### Deploy
Push `main` → GitHub Pages serves the repo root. Verify: `/sitemap.xml`,
`/robots.txt`.

## 4. Operations

- No env, no health endpoint (static). Monitor via Pages status + manual
  link check.
- Keep `sitemap.xml` `lastmod` in sync when a page's content changes
  (currently 2026-11-19).
- The verification harness (check, smoke, contrast, responsive, live-audit
  scripts) lives outside the repo in `~/shots/pf-harness/`.
- Roadmap: link-check CI, HTML validator run. Both are dev-time only; the
  site itself stays build-free.

## 5. Verification

```bash
python3 -m http.server -d . 8000
```
Then check `/`, `/projects.html`, `/contact.html`,
`/sitemap.xml`.
